# Mobile Calculator

One Expo SDK 57 / React Native / TypeScript app for **Android and iOS**, with a separate Express API in `backend/`. Calculations always come from the API. There is no database, authentication, web app, or offline arithmetic fallback.

```text
Expo Go on your phone → HTTP/HTTPS → Express API in Docker → JSON result
```

The mobile app lives at the repository root. `ios/` and `android/` contain native projects generated by Expo Prebuild, not separate UIs. **Use Expo Go for testing. No local mobile builds are required or part of the current workflow.**

## 1. Requirements

- Node.js 24 LTS and npm.
- Docker Desktop with Linux containers for the local API, or an already running HTTPS API on your VPS.
- Expo Go compatible with SDK 57 on an Android phone or iPhone.
- For a local API, the computer and phone must share a reachable network.

The iOS simulator requires macOS and Xcode. A physical iPhone can run Expo Go while the development server runs on Windows. Current Expo Go on a physical iPhone may require the CLI and phone to be signed into the same Expo account; follow the displayed instructions yourself. This project does not configure remote accounts or credentials.

## 2. Start the API locally

All commands start from the repository root.

```sh
docker build --target runtime -t calculator-api:local ./backend
docker run -d --name calculator-api -p 3000:3000 -e PORT=3000 calculator-api:local
docker logs calculator-api
docker inspect --format "{{.State.Health.Status}}" calculator-api
```

Wait for `healthy`. The image runs lint, type checks, and tests during construction. It contains only production dependencies and compiled JavaScript at runtime, and runs as the non-root `node` user. A health check requests `/health` on the configured port.

An **image** is the packaged API; a **container** is a running instance. `-p 3000:3000` forwards port 3000 on the computer to port 3000 in the container. `EXPOSE` in the Dockerfile alone does not publish a port.

Check from PowerShell:

```powershell
Invoke-RestMethod http://localhost:3000/health
Invoke-RestMethod -Method Post -Uri http://localhost:3000/calculate -ContentType 'application/json' -Body '{"a":8,"b":4,"operation":"add"}'
```

Expected responses: `status: ok` and `result: 12`.

For subsequent sessions:

```sh
docker start calculator-api
docker stop calculator-api
```

After changing backend code, rebuild the image and replace the stopped container with `docker rm calculator-api` followed by the `docker run` command above. An existing container does not automatically use a rebuilt image.

### Backend environment variables and your VPS

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `3000` | API listening port, integer from 1 to 65535 |
| `NODE_ENV` | `production` in Docker | Production behavior for Express |

The API listens on `0.0.0.0` inside its container. There are no secrets or database credentials to configure. `EXPO_PUBLIC_API_URL` belongs to the **mobile app**, not the API.

On your VPS, if an HTTPS reverse proxy runs directly on the host, use:

```sh
docker run -d --name calculator-api --restart unless-stopped -p 127.0.0.1:3000:3000 -e PORT=3000 calculator-api:local
```

Point the proxy at `http://127.0.0.1:3000` and expose your chosen domain over HTTPS with a valid certificate. If the proxy also runs in Docker, put both containers on the same Docker network and target `http://calculator-api:3000` instead. No cloud provider, registry publication, DNS configuration, credentials, or remote deployment is performed by this repository.

## 3. Configure and start Expo Go

```sh
npm ci
```

Copy `.env.example` to `.env.local` and set the correct API URL. For example, in PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Edit `.env.local`:

```dotenv
EXPO_PUBLIC_API_URL=https://api.your-domain.com
APP_VARIANT=development
```

Replace the example domain with your real API. For local testing choose the host from this table:

| Client | URL when the API runs on your computer |
| --- | --- |
| Computer terminal | `http://localhost:3000` |
| Android Studio emulator | `http://10.0.2.2:3000` |
| iOS simulator, API on the same Mac | `http://localhost:3000` |
| Android phone or iPhone | `http://COMPUTER_LAN_IP:3000` |
| iOS simulator on a Mac, API on another computer | That computer's LAN IP |
| Preview / production | Reachable public HTTPS backend URL |

Use `ipconfig` on Windows to find the computer's LAN IPv4 address. Allow the API port through the firewall on your private network. On a phone, `localhost` points to the phone, not your computer. A Docker container name is also not a phone-reachable hostname.

Start the app:

```sh
npm start
```

Scan the QR code with Expo Go on Android or the iPhone camera. `npm start` explicitly selects `expo start --go`. The shortcuts `npm run android` and `npm run ios` also start Expo Go; they do **not** compile native apps. The iOS simulator shortcut needs a Mac; on Windows use the QR code and a physical iPhone.

Allow Expo Go to access the local network if prompted. Native configuration plugins affect generated standalone projects, **not Expo Go's own permissions**. If Expo Go cannot reach local HTTP on your network, use your reachable HTTPS API. Connecting to Metro (the development server delivering the mobile code) does not prove the API is reachable. An Expo tunnel would expose Metro, not the API.

After changing the URL, fully reload the app; restarting `npm start` is also a simple way to refresh shell-provided values. Public variables are embedded into mobile JavaScript; never put secrets in `EXPO_PUBLIC_` variables. Changing the backend container's environment does not change an installed app's API URL.

## API contract

| Endpoint | Success |
| --- | --- |
| `GET /health` | `200 {"status":"ok"}` |
| `POST /calculate` | `200 {"result":12}` |

`POST /calculate` requires `Content-Type: application/json` and exactly these fields:

```json
{"a":8,"b":4,"operation":"add"}
```

`a` and `b` must be finite JSON numbers, not strings. Operations: `add`, `subtract`, `multiply`, `divide`.

Failures have a consistent shape:

```json
{"error":{"code":"DIVISION_BY_ZERO","message":"Cannot divide by zero."}}
```

- `400`: invalid body, malformed JSON, invalid operation, division by zero, or non-finite result.
- `413`: request larger than 4 KB.
- `415`: unsupported content type or encoding.
- `404`: unknown endpoint.

The app accepts a dot or a comma as the decimal separator, plus a sign toggle for phone keyboards. Thousands separators and scientific-notation input are not supported by the UI. Calculations use JavaScript floating-point numbers; this is a teaching calculator, not a financial precision engine.

## Checks

**Lint** checks code quality; **type checking** checks data types; **tests** check observable behavior.

```sh
npm run lint
npm run typecheck
npm test
npx expo-doctor
npm --prefix backend ci
npm --prefix backend run lint
npm --prefix backend run typecheck
npm --prefix backend test
```

Backend development without Docker is also available through `npm run backend:dev` after installing backend dependencies. Stop the container first if both would use port 3000.

Run the same HTTP contract tests against the real running container (PowerShell):

```powershell
$env:API_TEST_URL='http://localhost:3000'
npm --prefix backend test
Remove-Item Env:API_TEST_URL
```

Or run the test stage in Docker:

```sh
docker build --target test -t calculator-api-test ./backend
docker run --rm calculator-api-test
```

Check a different internal port:

```sh
docker run -d --name calculator-api-alt -p 3001:4000 -e PORT=4000 calculator-api:local
docker inspect --format "{{.State.Health.Status}}" calculator-api-alt
docker exec calculator-api-alt id
```

Request `http://localhost:3001/health`, then stop and remove `calculator-api-alt`. Its health check must also become `healthy`, and `id` must show a non-root user.

### Phone checklist — repeat on Android and iOS in Expo Go

- `8 + 4 = 12`, `8 − 4 = 4`, `8 × 4 = 32`, `8 ÷ 4 = 2`.
- Negative numbers, zero, and decimal inputs work.
- Blank/invalid input and division by zero show readable validation.
- Loading is visible and the submit button is disabled while a request runs.
- Editing an operand clears an old result; repeated taps do not send duplicate requests.
- Stopping the API shows a network error, never a locally calculated result.
- Restarting the API and tapping Calculate recovers without restarting the app.
- A slow/unreachable backend stops waiting after about 10 seconds.
- Text remains readable with larger font settings; the keyboard does not block controls.

Automated client tests use a deliberately different server result to detect accidental local arithmetic. They also cover connection loss, invalid server responses, timeout, and cancellation. Automated tests do not replace the phone checklist.

## Native source synchronization

Both `ios/` and `android/` are present at the root and intended for version control. Build outputs, Pods, local SDK paths, and signing credentials are ignored. Expo Go does not consume these projects, so **you do not need Prebuild to test normal UI or API changes**.

Source of truth: `app.json`, `app.config.ts`, dependencies, and `plugins/with-local-network.js`.

1. Review `git status` and preserve native changes before synchronization. Do not overwrite unknown/manual changes.
2. Express native customizations through Expo config/plugins so they can be reproduced.
3. Use the guarded command for native configuration or native dependency changes:

   ```sh
   npm run native:sync -- --android
   # macOS or Linux:
   npm run native:sync
   ```

4. The wrapper refuses dirty or untracked native files. Newly generated folders must be reviewed and preserved in Git before the next guarded synchronization. It does not create commits automatically.
5. **SDK 57 Prebuild recreates native folders by default.** The wrapper explicitly adds `--no-clean` to layer changes instead. Layering still changes files: review the diff afterward.
6. Only when all native changes are preserved and reproducible, request regeneration with `npm run native:sync -- --regenerate` (or add `--android` on Windows). This permits deletion and recreation of the selected native directories.
7. Inspect the native diff and configuration after either operation. UI-only edits do not require synchronization.

Expo skips iOS generation on Windows. These iOS sources were generated by Expo Prebuild in a Linux Docker container, without CocoaPods or an iOS build. A Mac or Linux environment can regenerate the sources; only a Mac can run the iOS simulator or compile iOS locally. Local mobile compilation is outside the current Expo Go workflow.

The checked-in native configuration defaults to HTTPS-only. `APP_VARIANT=development` enables local HTTP exceptions **when Prebuild runs**. The iOS development exception is deliberately broad to accommodate changing LAN IPs; it must not be shipped. Preview/production requires a real public HTTPS API URL and re-synchronization without development exceptions. Config rejects local/example hosts for explicit release variants. Checking the hostname does not verify DNS or backend availability; verify `/health` from the target network too.

If EAS is authorized later, remember: when native folders are uploaded, EAS does not automatically run Prebuild. Synchronize first, review the native configuration, and configure signing/credentials only with separate authorization. No EAS profile, remote build, submission, or deployment is enabled now.

## Repeatable video walkthrough

1. Show the shared screen and explain: "The phone sends the request; the API calculates."
2. Start the local container and show `/health` returning `ok`.
3. Open the app in Expo Go, enter `8` and `4`, choose Add, and show `12`.
4. Try dividing by zero and show the validation message.
5. Run `docker stop calculator-api`, then submit a valid calculation. Show the network error and the absence of an invented result.
6. Run `docker start calculator-api`, wait for `/health`, and retry successfully.

If your demo uses the VPS API instead, stopping the local container will not affect it. Use the VPS's authorized stop/start controls, or temporarily point the app at an unreachable test URL and reload it; restore the working URL afterward.

## Main files

- `src/components/Calculator.tsx`: shared native UI and loading/result/error states.
- `src/lib/api.ts`: HTTP requests, timeout, cancellation, response validation.
- `src/lib/calculator-input.ts`: input parsing only; no arithmetic.
- `backend/src/calculate.ts`: server-side validation and arithmetic.
- `backend/src/app.ts`: HTTP contract and error responses.
- `backend/src/server.ts`: listening port and graceful shutdown.
- `backend/Dockerfile`: tested multi-stage, non-root production image.
- `app.config.ts`, `plugins/`, `scripts/sync-native.cjs`: reproducible native configuration.

Removing the backend unit means removing `backend/` and its root convenience script. Removing the mobile calculator unit means reverting `src/` and the root configuration changes together. Native folders can only be regenerated after preserving any changes; reverting them alone can leave config and native sources out of sync.
